# Titan Modules

Titan provides built-in modules and separately installable packages. The origin
badge identifies the package owner; it is not a guarantee of delivery, durability
or a particular deployment integration.

| Tier         | Origin | Where it lives                                | Guarantees                                          |
| ------------ | ------------ | --------------------------------------------- | --------------------------------------------------- |
| **Built-in** | Built-in   | `@omnitron-dev/titan/module/*`           | Ships with the framework; same release cadence     |
| **Official** | Official    | `packages/titan-*` in the `omnitron-dev` monorepo | Maintained in the Omnitron workspace |
| **Community**| Community     | Third-party npm packages                      | Audit before adopting; no maintenance commitment    |

Every module page in this section starts with a `<span class="module-badge"></span>`
chip that reflects its tier.

> Want a view of how the modules connect — who
> depends on whom, which combinations form common stacks, when to
> prefer one over a similar one? Read the **[Module map](./module-map.mdx)**.

## Built-in modules {#built-in-modules}

<span class="module-badge">built-in · @omnitron-dev/titan · /module/*</span>

Config and Logger ship inside `@omnitron-dev/titan` and are **auto-loaded**
unless you pass `disableCoreModules: true`. RLS guards are imported explicitly.
No extra Titan package is needed for these entry points.

| Module                        | Subpath                  | Purpose                                                                |
| ----------------------------- | ------------------------ | ---------------------------------------------------------------------- |
| [`ConfigModule`](./config.mdx) | `/module/config`         | Layered, validated, hot-reloadable configuration                       |
| [`LoggerModule`](./logger.mdx) | `/module/logger`         | Structured pino-based logging with transports + processors             |
| [RLS guards](./rls.md) | `/module/rls` | Context guard decorators; no module registration |

## Composition {#composition}

Declare the imports required by the providers you actually use:

```typescript
import { Module } from '@omnitron-dev/titan';
import { TitanAuthModule } from '@omnitron-dev/titan-auth';
import { TitanCacheModule } from '@omnitron-dev/titan-cache';
import { TitanMetricsModule } from '@omnitron-dev/titan-metrics';

@Module({
  imports: [
    TitanAuthModule.forRoot({ jwtSecret: process.env.JWT_SECRET }),
    TitanCacheModule.forRoot({ maxSize: 1_000, defaultTtl: 60 }),
    TitanMetricsModule.forRoot({ appName: 'my-api', storage: { type: 'memory' } }),
  ],
})
export class AppModule {}
```

Config and Logger are core modules by default. An SQL backend, cache L2 adapter,
Redis client or relay transport requires its own wiring. Importing a module does
not make every package consume its connection automatically.

## Redis dependency among official modules {#redis-dependency-among-official-modules}

| Consumer | How it gets Redis |
| --- | --- |
| `titan-lock` | `REDIS_MANAGER.getClient(redisClientName)` |
| `titan-discovery` | Shared manager's internal client, or its own connection from `redisUrl` / `redisOptions` |
| `titan-ratelimit` | Default Redis client token for Redis storage; see async-factory caveat in its guide |
| `titan-notifications` | Explicit `redis`, otherwise optional managed client; Rotif creates dedicated connections from those options |
| `titan-cache` | Caller supplies an `IL2CacheAdapter` in `l2.client`; no automatic Redis lookup |
| `titan-scheduler` | Caller constructs `RedisPersistenceProvider` with a compatible client |

See the [module map](./module-map.mdx#where-redis-sits) for connection ownership.
Redis persistence, Streams retention and locking guarantees are separate concerns.

## Choosing modules {#choosing-modules}

Most backends start with a small set:

- **Web API service**: built-in config + logger; auth + database +
  cache + health + metrics.
- **Worker service**: built-in config + logger; database + lock +
  scheduler + metrics + health.
- **Notification gateway**: built-in config + logger;
  notifications + ratelimit + metrics.
- **Multi-instance app**: add discovery to the above.

→ Start with [`ConfigModule`](./config.mdx) for built-in config or
jump to [`TitanAuthModule`](./auth.mdx) for the most-used official
module.

→ Want to build your own? Read
[Authoring a module](../modules-system/authoring-modules.md) — the
step-by-step recipe every official `titan-*` package follows.
